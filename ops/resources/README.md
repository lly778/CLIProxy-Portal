# 整机资源保护与监测

入口：**系统管理 → 资源保护**。默认观察模式，只记录并放行，不修改任何容器上限。点击“设置”打开弹窗，管理员登录后直接保存设置，保留权限与 CSRF 校验；过期页面不能覆盖新的设置。

## 总量预算与实时显示

- 实时显示整机 CPU 使用率、已用/总内存、可用内存、当前并发、待完成工作、保护状态。实时资源指标取采样缓存，页面可见时每五秒刷新，不覆盖未保存的表单。
- 默认全局并发 2、每用户并发 1、单请求 10 MiB、整机 CPU 90%、整机已用内存 768 MiB。所有数值项均支持填 0 表示该项不限。非零内存上限须至少低于整机总内存 64 MiB；已用量为 MemTotal 减 MemAvailable，可回收缓存不当作已用内存。
- 总量包含门户、CPA、CPAMP、隧道和其他后台工作。CPU 持续超限 15 秒或内存达到上限时暂停新模型请求；CPU 回落 15 个百分点（低阈值时降至一半）且内存低于上限 32 MiB，稳定十秒后恢复。启用 CPU 或内存保护时，监测十秒未更新会暂停新请求。
- CPU 和内存预算用于控制新请求准入。已有请求继续处理，因此短时仍可能超限，无法保证完全杜绝 OOM；不设置或变更单个容器的 CPU/内存限制。
- 策略随门户数据库备份恢复；“近 7 天内的保护记录”按持久化系统日志统计最近 168 小时的拒绝和观察放行次数，门户重启不清零，不受日志列表最近 100 条限制。统计读取失败时显示“—”，删除对应日志会同步减少计数。
- 每次保护触发均单独进入系统日志，时间显示沿用既有系统日志格式，不合并记录，日志不含请求内容或完整 Key。日志结果统一显示中文，表格不再展示来源列，后台仍保留来源字段；关联对象列加宽并居中，详情保持左对齐，内容完整显示。
- CPU、内存超限或监测不可用时，资源保护区域使用红色提示条显示原因。保护模式说明新请求暂停、已有请求继续及自动恢复；观察模式说明仍会放行。恢复正常后隐藏提示，不显示“正常”徽标。

## 最近 60 分钟趋势

CPU 与已用内存在同一张图中展示，共用当前时刻向前滚动 60 分钟的时间轴。CPU 使用左侧百分比坐标，内存使用右侧 MiB 坐标，不按整点分段。悬停或聚焦图表后使用左右方向键，可同时查看两项指标及具体采样时间。

复用每两秒的整机采样，每 10 秒分别保留 CPU 与内存的峰值；同一时间桶内的两个峰值不一定发生在同一瞬间。图表每 15 秒刷新，页面隐藏时暂停请求，刷新失败时保留上次曲线并提示。监测中断处不连线，首次启用时从实际采集时刻开始累计。

内存中最多保留 361 个时间桶，每分钟及正常退出时将最近一小时样本保存到门户数据库的 `resource_history_v1` 设置项。重启后恢复已保存的有效样本，过期、无效及未来时间的数据不展示；异常退出可能丢失最后一分钟未保存的样本。历史接口仅管理员可访问。

## 请求保护

门户 Key 按用户合并计数，其他 Key 共用一个额度。POST `/v1/`、`/v1beta/`、`/backend-api/`、已支持的推理路径和 WebSocket 升级受保护；登录、管理、健康检查不占额度。SSE 和 WebSocket 在整个请求/连接期间持有额度，取消及上游错误释放；全局并发为非零时，后台交互记录达到全局并发加四会暂停新请求。

并发超额返回 429；总资源压力、监测中断、记录积压返回 503，附 `Retry-After: 5`。请求传输大小或任一解压阶段超限返回 413，无效压缩返回 400，未支持编码返回 415。客户端仍应遵守重试间隔。

启用保护时先用临时文件检查大小，再向 CPA 转发原传输字节，支持 identity/gzip/deflate/zstd（最多三层）。WebSocket 按完整消息（含分片）检查大小并关闭压缩协商；超限连接终止。观察模式只检查传输大小、并发及资源压力，不额外解压或解析 WebSocket 消息。

## 轻量监测

门户现有后台每两秒读取 `/proc/stat` 和 `/proc/meminfo`，实时状态与固定容量的趋势缓冲保存在内存。趋势按上述周期写入已有 SQLite 数据库，不创建独立采样文件、不启动额外进程、不调用 Docker API。近七天计数查询使用资源事件专用索引，不读取请求正文。

适用于当前标准 Linux Docker 部署，容器内 proc 计数须与宿主机一致；当前 VPS 已实际比对。若部署使用 lxcfs 或其他 proc 虚拟化，需先核对数据口径。无法取得有效采样时显示监测不可用，保护模式暂停新请求。

升级门户即可使用，不需要额外的宿主机服务、Docker socket、配置文件或容器限额。默认观察模式，确认正常流量后可在面板启用保护。
