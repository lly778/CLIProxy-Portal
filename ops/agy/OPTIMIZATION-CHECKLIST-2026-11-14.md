# AGY 桥接与工具转接优化清单

更新：2026-11-14，Asia/Hong_Kong。基线：`8903654`。

用户要求优化桥接整体、工具调用、工具转接三个方面，并先形成清单；追加核查此前尚未实现的工具转接。本文是实施清单和验收依据。A1–A3、B1–B4、C1、C3 的明确目录服务端发现及受限远程 MCP broker，以及 D1、D2、D4、D6 已补实现与协议夹具测试，并于 2026-11-14 19:45 +0800 部署。D3 第六批另补进程/接收代次/完成边界和有界旧工具 ID 隔离，新增部分尚未部署；真实无身份迟到文本仍有边界。D5 完成方案评估。C2、C4 和托管检索/解释器仍待运行时或独立后端。Git 状态以包含最新记录的实际提交和远端分支为准；各批次“未部署/推送”文字保留当时状态。

## 当前基础与实施边界

已具备：Responses → ACP 会话控制、会话独立回环 MCP、客户端工具执行、同回合结果续接、历史与所有者校验、工具发现及动态定义校验、普通追加 FIFO、重连复用、原会话生成 Codex 摘要、Google 官方搜索和生图。

继续保持客户端默认窗口 500,000 tokens、当前 AGY 检查点补丁 512,000、桥接 160 KiB 单次文字预算。三个限制含义不同，本清单不自动改变任何一个限制。继续保留客户端执行文件/终端/电脑操作的边界、普通空工具名单撤销语义、工具结果优先于排队消息的规则。

不因工具名字相同或参数相同就全局去重；原生服务端已执行工具不能重新变成客户端任务。执行成功只来自可验证的实际结果，不能由“已生成调用”或“已生成摘要”推断。

完整会话检查点仍以移出内存等既有时机保存；新增轻量回执与完整快照分开，避免重新引入每轮全量写盘。凭据和任意原始 stderr 不进入普通日志。测试优先使用协议夹具，不主动消耗真实模型额度；客户端自然请求另作验收证据。

## 优先级和实施顺序

- P0：影响结果可信度或消耗核算，优先实施。
- P1：提升可观测性和转接完整性，按依赖实施。
- P2：先验证协议/运行时能力，满足条件后再启用。

第一批：A1、B1、A2。第二批：B2、B3、B4、C1。第三批：A3、C2、C3 的能力与协议验证。需要独立托管后端的功能单独立项。

## A. 桥接整体

### A1 — P0：内部摘要调用用量核算

- [x] 第一批实现和本地验证；生产自然请求验收待部署后进行。
- 证据：`internal/agy/compact.go` 的 `summaryTurn` 只返回文字；`executeCompactHTTP` 明确输出 `usage: nil`。普通长历史导入与显式压缩仍可能调用分段摘要，Codex 固定摘要原会话路径不再有这层预摘要。
- 改动：为摘要调用采集真实原生用量，按所属请求关联主调用/摘要调用；记录实际调用次数及摘要缓存复用。内部摘要目前使用 `internal-summary` 会话所属标签，需要另行保留真实请求所属用户/Key 的核算关联。
- 账本累计实际消耗；返回客户端的 `usage` 保持对应响应的语义，不能把独立摘要会话的输入量伪装成主会话上下文大小。缓存/思考作为 input/output 的子集展示，不二次相加。
- 验收：分段三次加主调用一次可追溯四次；缓存复用和完成响应重放不重复累计；部分失败仍保留已经发生且可证实的用量；未知用量明确为未知，不估造零值或 token 数。
- 范围：`compact.go`、`native_usage.go`、`tracker.go`、`internal/gateway/agy.go` 及实际统计存储路径。

### A2 — P1：请求阶段与转接耗时

- [x] 第一批实现和本地验证；生产自然请求验收待部署后进行。
- 现状：已有上传/等待/响应计时及排队 SSE 事件，缺少贯穿原生回合与多个工具往返的完整阶段记录。
- 改动：关联请求、响应、原生会话、工具批次；记录排队、恢复会话、生成、等待客户端结果、摘要、交付等阶段，以及原地续接/磁盘恢复/历史重建的原因。
- 验收：一条慢请求可直接定位主要耗时；重试、排队和等待工具不被误报为生成失败；心跳不算模型进度。展示放在请求详情，保留既有概览和资源卡片布局要求。
- 范围：`responses.go`、`followup_queue.go`、`session_cache.go`、网关计时、请求详情。

### A3 — P2：运行时指纹及能力记录

- [x] 本地实现与协议回归；自然运行时证据待部署采集。
- 证据：`Manager.ensure` 当前验证 ACP v1 并读取 `loadSession`，没有保留完整能力证据。
- 改动：记录程序版本/哈希与握手能力；能力使用 supported/unsupported/unknown 三态；CLI 更换后使旧证据失效。分别说明配置值、协议声明和实测能力，不把本地补丁推断成实际模型容量。
- 验收：程序升级后不会沿用旧的目录刷新、恢复或传输支持结论；失败原因可关联运行时版本；探测不发模型推理请求。

## B. 工具调用

### B1 — P0：实际执行回执与调用分类

- [x] 第一批实现和本地验证；生产自然请求验收待部署后进行。
- 证据：`response.call` 中 `function_call.status=completed` 表示调用生成完成；客户端执行是否成功要等真实结果。长任务另有 `portal_await_tool`，不能把等待次数当作文件修改次数。
- 改动：独立记录派发、结果收到、结果交付等事实；成功/失败从客户端结果字段中提取，无退出状态或其他可验证成功标记时保留“结果已收到/执行结论未知”。记录 call_id、原会话、工具身份、定义版本、参数/结果摘要及时间，不默认额外保存原始正文。
- 分类：客户端实际操作、Google 原生工具、工具发现、描述工具、等待原结果、HTTP 重试/响应复用。
- 验收：能区分“发出保存命令”和“收到保存成功回执”；重复重连不增加实际操作计数；内容相同的新请求不被误挡；回执不声称实现跨客户端崩溃的 exactly-once。
- 范围：`mcp.go`、`responses.go`、`turn_recovery.go`、`response_replay.go`、存储及请求详情。

### B2 — P1：批次记录与缺失结果诊断

- [x] 本地实现与回归通过；生产自然请求验收待部署。
- 现状：已有 150ms 有界收集、按调用 ID 匹配、整批结果校验，校验失败不提前释放 MCP 等待。
- 改动：为已交付批次记录 ID、调用清单、结果收到情况，错误可定位缺失的调用；批次身份随恢复和响应复用保留。没有原生批次结束信号时继续有界收集，不无限等待，也不假定所有后续调用属于同一批。
- 验收：乱序回传、缺一条、重复条目、不同内容重传、批次间混入、并行关闭与迟到结果均正确处理；串行请求仍只允许一个未完成动作。

### B3 — P0：JSON 数字完整性

- [x] 本地实现与回归通过；生产自然请求验收待部署。
- 证据：`tool.UnmarshalJSON`、MCP 参数及部分结果解码使用默认 map 数字类型；`schema.go` 的数字校验依赖 `float64`，大整数存在精度风险。并未据此认定历史任务已发生数值篡改。
- 改动：统一数字解码、校验、序列化、摘要哈希与历史复制策略；考虑 `UseNumber`，同步适配原生动作参数校验和恢复兼容，不能只改入口。
- 验收：9007199254740993、大整数 enum/const、负数、小数及指数记法往返不变；非法或过大数字有界拒绝；旧合法缓存/重试仍能识别，不能为兼容而放松结果身份校验。
- 范围：`request.go`、`mcp.go`、`schema.go`、`native_tools.go`、内容与历史复制路径。

### B4 — P1：执行来源与取消恢复回归

- [x] 清单列出的本地组合回归已补齐；后续实际运行差异继续补充。
- 已具备：官方工具与客户端工具分开输出；迟到结果按真实已完成动作续接；MCP 等待取消不声称客户端程序已停止。
- 扩充：为客户端、Google 原生服务、门户内部等待/发现明确来源；把压缩、重连、进程退出、定义撤销、等待取消组合进协议回归。
- 验收：原生已执行工具不会被转为待客户端执行的 function_call；历史调用只作上下文；取消等待后收到成功结果仍能准确反映，结果未知不能变成成功。

## C. 工具转接

### C1 — P1：定义版本、投影与结果完整往返

- [x] 本地实现与协议回归；定义缓存、当前授权、版本和拒绝原因均接线。
- 现状：原始 Schema 与面向 AGY 的投影分离；大工具可通过 `portal_describe_tool` 读取，再经 `portal_call_tool` 调用；原始定义用于最终参数校验。
- 改动：绑定完整工具身份、原始定义摘要、投影版本和执行来源；缓存有效定义的描述，避免不必要的重复获取；记录直接调用/通用转接比例及参数拒绝原因。保留命名空间隔离。
- 验收：复杂 anyOf/$ref、非字符串 enum、自定义原文、换行/反斜杠/Unicode、图片、结构化字段、资源引用、退出码与错误标记完整往返；定义更新或撤销后旧通用入口不能继续执行。资源链接存在不等于内容已被模型读取。

### C2 — P2：动态目录原生刷新

- [ ] 尚未通过实际运行时的通知触发重拉验证；已补默认关闭的候选通道及鉴权、撤销、挂起调用回归，见第四批记录。
- 证据：当前 `tools/list` 使用初始 `advertisedTools`，MCP 初始化未声明 `listChanged`；更新主要走最新策略校验和通用调用入口。MCP 规范定义了 `notifications/tools/list_changed`，但尚未验证本项目 AGY 1.5.3 会重新获取并采用目录。
- 方案：用协议夹具验证通知/重新获取流程，再观察明确授权的客户端自然调用；只有运行时确实刷新时才启用原生更新。否则保留稳定目录与通用调用，不因刷新失败重建正在等待工具的会话。
- 验收：新增、修改、撤销及工具发现都不破坏原挂起调用；禁止“发出通知就报告模型已加载新工具”。

### C3 — P1：未实现工具转接的补齐路线

下列逐项列出状态。服务端工具发现及受限远程 MCP broker 已实现并通过本地假服务验收，真实远端/客户端联调仍待进行；托管执行器按真实来源保留边界。

| 功能 | 当前缺口 | 建议路线 | 外部依赖与验收 |
| --- | --- | --- | --- |
| 远程 MCP（server_url 声明） | 已补受限 broker 并部署；尚未进行真实远端联调 | 按所属用户/会话隔离，真实 initialize/tools/list → 授权目录 → 审批 → tools/call → mcp_call；原 MCP 结果保留 | 仅公共 HTTPS Streamable HTTP、allowed_tools 名称数组及 require_approval always/never。默认审批；每轮重供远端自己的 bearer，不转发门户/Google 凭据；在途未知结果不自动重发。详见第五批 |

| OpenAI 托管 code_interpreter | 缺少托管容器、持久内核和产物服务 | 本机 Python/终端任务继续用客户端执行器。托管模式另接明确的会话执行后端，再做调用与文件产物适配 | 原 CLI 自带 run_command 或服务器随手运行 Python 不等同于托管解释器；本清单不新增门户任意代码执行 |

### C4 — P2：MCP-over-ACP 作为后续传输选项

- [ ] 暂列研究，不替换现有传输。
- ACP Go SDK 存在不稳定 MCP-over-ACP 扩展；`agy-gateway` 对运行时 1.4.5 的记录只声明 HTTP/SSE。我们不能据此推断当前 1.5.3 支持该扩展。

## 第一批落地记录（2026-11-14）

- A1：内部摘要从真实 native usage steps 读取用量，保留真实请求所属用户、Key、request/session ID、已确认模型调用数；缓存命中独立记录。摘要开销进入独立去重账本并并入门户 Token 汇总，HTTP 调用数和返回客户端的 Responses usage 语义保持不变。失败摘要保留已确认消耗并提示可能不完整；缺失数据不伪造已知零值。
- B1：分别记录 issued、dispatched、result_received、result_delivered、wait_cancelled、context_prepared。issued/dispatched 只代表生成或写入桥接响应，不代表客户端已执行；context_prepared 只代表迟到结果已整理，不能当成已送达。结果按明确 isError/is_error、原生 shell exit_code/timeout、原生 apply_patch 状态判断，普通文本保留 unknown。await、describe、tool_search、Google 官方工具、HTTP 响应复用独立分类。参数、结果与工具定义仅保存哈希。
- B1：使用 owner/session/call/state 的稳定身份保存轻量回执，完整批次验证后才记录新结果；重复结果不增加回执。相同参数的新调用保留独立 ID。等待快照只追加原始观察 request/session 标识，继续遵守移出内存时保存完整快照的规则。

## 第二批：续接和工具稳定性（2026-11-14）

本批按用户最新重点实施：减少桥接丢失已知信息、误判为新任务、吞掉追加指令所造成的重复。未启用新远程执行器或更换 ACP/MCP 传输。

### 已修复的具体路径

1. **工具结果缺少 previous_response_id**：按当前所属用户的原始 call_id 找到会话后，把原始历史与结果增量正确衔接；不再将结果列表单独作为重建上下文。已经在原历史中的相同结果保留一份，新追加消息仍可进入原对话队列；同一输入中的重复条目仍拒绝。
2. **旧结果承接了新指令**：完整历史同时回传多个批次结果时，追加消息和工具定义更新仅挂到尚未交付给 AGY 的结果上；不能因字典序较大而选中已经交付的旧调用。没有可承接结果时，明确返回冲突，不把新增消息标记为已处理。
3. **重建丢掉未完成调用**：取消原会话之前，用隔离副本校验全部挂起工具的结果、调用类型、定义和结果身份。缺失、未知、类型不符或改写的结果不取消原等待、不修改原策略、不唤醒真实 MCP。结果齐全后才允许按明确的新上下文重建。
4. **结果已消费但尚未写入 HTTP 历史**：移出内存时，从已确认 Ready 的原调用保留实际结果到加密检查点，覆盖已通过 MCP 交付或已整理为续接上下文的情形。没有结果的调用保留等待，不凭空生成完成回执。原始结果在历史中保留一份，待处理工具从该历史恢复其 wire 结果，不增加第三份结果副本。
5. **同时恢复同一磁盘记录**：按原生 session ID 和已有响应链抢占恢复权；同一记录的两个解码副本不能并行 load/new，已经被续接的新会话不能被旧记录再次创建。恢复会话在首个处理器绑定请求锁之前维持 loading，避免其他请求提前抢走未完成的恢复流程。
6. **失败标记丢失**：MCP isError/is_error 在转换为迟到结果或摘要上下文时保留明确失败说明，图片和 structuredContent 同时保留。原生 apply_patch 的 completed/failed 以及 local_shell 的 incomplete 属于执行事实，不能作为普通传输 status 忽略。

### B2 批次记录

- 每个实际派发响应分配 batch ID，调用清单、结果收到、结果交付和缺失诊断均可关联；等待快照保留 batch ID，HTTP 重放保留原响应和调用身份。
- 缺少结果时返回原 call_id 供定位；错误批次不提前释放任何 MCP 等待。完整历史中已存在的旧结果可回放，未知的新结果不可静默忽略。函数/自定义工具结果与原调用类型匹配；缺少 output 不再被当作显式 null 结果。
- 门户错误详情的新错误类型继续显示英文；面向调用客户端的原中文风格保持。

### B3 精确 JSON

- 工具原定义、MCP 参数、结果、工具发现、历史复制、加密缓存恢复全链路使用 json.Number。enum/const、数字/整数判定、原生超时/退出码/坐标校验、Schema 投影和哈希同时适配。
- 9007199254740993 等不同大整数保持不同；嵌套数字和科学记法不经 float64 舍入。原始文本和函数 arguments 字符串不改写；哈希对等价数值采用稳定表示，仍识别此前可精确表示的普通数值。数值字面量上限 256 字节，显式指数绝对值不超过 1024；超界明确拒绝。
- 保持持久 HTTP replay key 原有算法，避免升级后无故失去已缓存响应；历史索引升级至 exact-numbers-result-status-v3，从已有加密 wire 历史一次性重建索引，读取时刷新对应指纹，保留原生会话 ID 和 Key 隔离。

### 验证与边界

- 协议回归：无 previous_response_id 的结果续接仍使用原 native ID；重建前拒绝不完整/类型错误结果；已交付/已整理结果在检查点中保留；缺失/乱序/重复/未知混入结果；新指令与定义更新只交给未交付结果；重复结果后追加消息可排队；并发冷恢复仅一次 session/load，旧响应链不能复活。
- 精度回归：大整数定义/参数/结果/复制/磁盘恢复完整往返、嵌套 const/enum、整数科学记法、原生坐标和超时精确边界、随机有限 float 的旧哈希兼容、既有原生结果状态索引升级。现有压缩、授权撤销、取消、官方工具来源和移出内存时保存检查点的回归继续运行。
- 检查：`go test ./... -count=1 -timeout=120s`、`go vet ./...`，另构建 Linux amd64；仅使用协议夹具，不发起真实付费模型请求。构建产物放在系统临时目录。
- 仍按原规则在移出内存时保存完整会话，没有改为每轮全量写盘。进程硬崩溃前尚未落盘的驻留状态仍可能不可恢复；客户端执行器不提供幂等承诺时，也不能保证网络断线或崩溃下绝对不重复。桥接不能强迫模型永不重复，只能保留已知事实、维持身份、拒绝不确定回传并避免自动重发已执行动作。
- 当前为本地修改，尚未推送、部署或观察生产自然调用；不得把这些测试结果表述为线上已生效。
