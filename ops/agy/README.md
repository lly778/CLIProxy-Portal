# Antigravity ACP 接入

门户容器内运行 Go 桥接逻辑，使用外部只读挂载的官方 `agy acp` 和回环 MCP 桥；客户端仍通过门户的 Responses HTTP/SSE 接口调用。项目文件、终端和电脑操作由客户端执行。AGY 仅开放官方 `search_web`、`read_url_content` 和 `generate_image`，其余服务器文件/终端权限请求默认拒绝。配置运行服务并登录后，已审批的门户用户可调用管理员启用的 AGY 模型。

## 工具续接与会话恢复

客户端服务工具同时接受 Responses 函数定义、Chat Completions 的嵌套 `function`、DSH/Anthropic 的 `input_schema` 和 MCP 的 `inputSchema`。命名空间保持完整身份；客户端已经连接并展开的 MCP 工具可作为函数回传，显式 `execution: client` 的 MCP 工具定义列表也可展开。带 `server_url` 的远程声明走下述独立 MCP broker，由明确连接的远端执行。

网页搜索、网页读取和图片生成统一使用官方 Google 工具。旧的客户端搜索、生图专用适配已删除；初始声明、动态发现、历史工具引用、缓存恢复和调用校验均过滤对应的旧工具，避免混用。文件检索、Python、通用 MCP 及图片查看/回传继续使用客户端执行器。大型工具说明、延迟发现及原始参数校验沿用同一套桥接。

搜索来源和文档文字、MCP 文本资源/资源链接、结构化结果、Anthropic base64 图片及图片生成结果可回填。远程图片地址只作为链接提供，不声称已读取像素；网关不会自行抓取 URL、读取本机文件或解释二进制 PDF。客户端已经提供的历史搜索、图片生成、远程 MCP 等服务记录只用于上下文，不会重新执行。

网页搜索、网页读取和生图直接使用已登录的官方 AGY 服务，不依赖客户端安装对应执行器或另配 DeepSeek 搜索 Key。远程 MCP 需请求者提供相应服务的连接和授权；门户没有托管 Shell/代码解释器。

官方工具通过 CLI 插件白名单启用，`PreToolUse` 调用桥接程序的轻量检查入口，核对正在运行的所属会话和本次 `tool_choice`。内部摘要、禁用工具及不匹配的工具范围均不能调用。生图暂不读取 `ImagePaths` 本地参考文件，图片名只能是文件名片段，防止跨用户或服务器文件访问。上下文预算补丁见下文，不修改工具执行或权限代码。

搜索和网页读取回传 Responses `web_search_call`；生成图片以 `image_generation_call.result` 返回真实 PNG base64，补齐图片完成事件。ACP 不直接携带生图文件时，门户仅从当前官方会话目录读取本次新生成的图片。生图开始事件的 `result` 使用空字符串，符合 Codex 的原生图片类型。AGY 的 `part_0` 等内部占位图片地址会跨流式片段转换为内嵌 PNG 预览（最长边最多 192 像素、整个数据 URL 最多 64 KiB），同时附上原图下载链接；模型未输出图片标记时也会补齐预览。原始 PNG 像素继续保留在原生图片结果和公网签名下载链接中，不依赖 Markdown 的远程图片加载，不暴露服务器路径或 API Key；签名仅允许访问指定图片，有效期七天，缺失或篡改签名返回 404。查看图片不计为模型请求，也不查询用量数据库。单张 PNG 上限 4 MiB、解码尺寸最多 4 百万像素，图片与文字合计上限 12 MiB。用量跟踪保留 16 MiB 有界响应限制。生成图片、官方会话目录与磁盘会话按同一规则在闲置超过七天后清理。旧磁盘会话下次使用时从保存的历史重建，以获得新的官方工具配置和客户端工具过滤规则。

- 工具结果可以同时携带用户、开发者或系统追加指令；图片保留为多模态内容。AGY 先结束本轮、客户端工具后完成时，使用真实结果续接，不再次执行已完成动作。
- 客户端改写、压缩历史或更新系统指令时，校验后重建原响应链。恢复索引加密保存对应的完整请求历史，历史工具记录仅作为上下文。旧版缓存缺少重建历史时，需要客户端提供完整对话。
- Codex 回传时可能交换同一段思考摘要与工具调用的顺序，也会为思考记录补入 `content: null`、`encrypted_content: null`。桥接统一相邻思考/调用记录的比较顺序，并将这两个可选字段的缺省与 null 视为等价；非空内容仍严格匹配。保留全部内容及调用之间的顺序，不跨用户消息、工具结果或可见回复移动记录。正常续接仍复用原 ACP 会话，工具结果直接回到等待中的 MCP 调用；上述格式变化不再触发完整历史重放。模型、系统指令及历史内容实质改变时仍重建。
- 相同请求按执行状态续接或复用结果。请求身份同时绑定门户用户、Key、接口、会话/轮次标识或响应链，以及完整请求参数；支持 `Idempotency-Key`、Codex 会话/轮次元数据及客户端请求 ID。相同标识但参数改变时按新请求处理。缺少稳定标识时正常执行，不凭文字相同拒绝请求。同一会话仍按请求锁串行处理，并校验工具结果的调用归属。
- 支持 `tool_choice` 的自动、禁用、必须使用、指定工具及允许工具范围；`parallel_tool_calls: false` 限制同一会话同时只执行一个客户端工具。独立对话可以并发，上限沿用常驻会话配置。
- 复杂参数定义在发布给 MCP 时适配本地引用、组合类型、可空类型和元组；实际调用继续校验原始定义。大型工具精简发布描述，必要时通过 `portal_describe_tool` 读取完整原始定义，再用 `portal_call_tool` 分发；这两个辅助工具不执行宿主机命令。
- 支持客户端函数形式的 `ToolSearch` 返回 `tool_reference`，只解锁本次请求中实际声明的工具；原生客户端工具搜索仍然可用。调用 ID 改写仅在完整历史严格匹配时接受。
- 输出达到上限后最多自动续写 3 次。MCP 单项取消只取消相应等待，不声称已经停止客户端中运行的程序。MCP 风格失败标记与图片结果可以一起回传。

### 远程 MCP broker（已部署，待真实联调）

支持公共 HTTPS 的 Streamable HTTP 服务，按请求真实执行 initialize/tools/list，返回 `mcp_list_tools`，按原始 schema 校验模型参数。工具执行完成返回自含的 `mcp_call`；不会同时给客户端一个需要再次执行的函数调用。协议依据为 [MCP Streamable HTTP](https://modelcontextprotocol.io/specification/2025-06-18/basic/transports) 及 [Responses MCP 审批语义](https://developers.openai.com/api/docs/guides/tools-connectors-mcp)，支持范围以本节为准。

声明示例（模型、地址和凭据须换成自己的值）：

```json
{
  "model": "agy/<已启用模型>",
  "input": "使用已连接的文档服务读取项目记录",
  "tools": [{
    "type": "mcp",
    "server_label": "docs",
    "server_url": "https://your-mcp.example/mcp",
    "authorization": "<该远端服务自己的 bearer token>",
    "allowed_tools": ["read_record"],
    "require_approval": "always"
  }]
}
```

默认 `require_approval=always`，模型发起操作时先返回 `mcp_approval_request`；继续请求使用原 `previous_response_id`，在 input 中传 `{"type":"mcp_approval_response","approval_request_id":"<原审批 ID>","approve":true}`，并重新提供原 tools 声明及该远端授权。`approve:false` 直接拒绝，不执行远端操作。批准只是授权，不代表执行成功；只有实际工具结果能确认执行状态。明确指定 `never` 才跳过审批。

`allowed_tools` 当前只接受名称数组，省略表示该服务实际公布的全部工具，空数组表示全部禁用。`require_approval` 只接受 always/never；尚不支持过滤对象、逐工具审批对象、任意 headers、legacy SSE transport 或托管 connectors。最多 4 个服务，当前工具总数最多 256。仅 URL 可以发现目录，默认仍须审批才执行；没有可用连接或授权时明确失败。

原始远端 bearer 仅在当前请求和必要的在途操作内存中使用，不写入模型定义、恢复快照、普通日志或回复，也不从旧请求继承；不向远端转发门户、Google 或其他服务凭据。声明、授权账号、schema 或 tool_choice 改变时重新校验，旧审批不能授权另一个账号/契约。拒绝私网/回环/保留地址、URL 中的账号或查询参数、重定向和环境代理，每次建连重新验证 DNS 地址。

同一原生请求 ID 的重传复用同一个动作；工具执行前保存轻量尝试标记，未知执行结果不自动重发。原生先结束时等待实际远端结果并续接；重启后保留实际结果或明确 unknown，未派发的已批准动作需要本轮授权。执行全局最多 3 个、每原生会话 1 个，默认执行等待上限 10 分钟；每会话新增结果记录预算 10 MiB，恢复后继续计入。图片、结构化内容和大整数保留，结果过大或不可表示时明确报告未知结果，不截断后冒充成功。尝试标记保留 7 天，账号切换/退出清理；不能保证外部服务、断电或新动作 ID 下绝对只执行一次。

本地假服务覆盖审批、执行、拒绝、早结束、重传、冷恢复、压缩及容量边界；尚未进行真实服务或 Codex 客户端验收。客户端项目文件仍通过客户端执行器访问，远端执行的位置由明确连接的 MCP 服务决定。

### 重试续接与结果复用

已识别的重试在原请求仍执行时订阅同一次输出，不再次提交官方模型；完成后返回原响应，响应 ID、事件顺序及工具调用 ID 保持一致。已回传的工具结果沿用原调用和续接结果。明确失败且没有完成响应时可正常重试，不保留“结果未知”拒绝记录，也不扫描官方会话错误判断是否恢复。

客户端断开后保留 30 秒重连时间，重新连接时继续原请求；无人重连则取消后台 HTTP 执行。每个正在交付的响应暂存最多 32 MiB，完成结果加密保存在 AGY 恢复索引中，有效期 10 分钟，最多 128 份且合计不超过 64 MiB；普通重试只按键读取对应缓存，不扫描完整会话或模型目录。过期记录在写入或启动时清理，容量压力时淘汰较早结果。已完成缓存可跨门户进程重启复用，切换或退出 Google 账号时清除；重启前仍在执行的原生任务无法保持实时连接，后续请求仍按现有历史恢复规则处理。缓存是有限时间内的结果复用，不保证外部客户端或进程崩溃场景中的操作恰好执行一次。

请求日志保留每次 HTTP 尝试；同一 Key 重复收到同一个响应 ID 时，仅首次有实际用量的记录累计模型 Token，避免重试复用结果重复计入全局或个人统计。传给客户端的原响应和用量字段保持原值。服务日志以 `AGY response reused` 区分续接正在执行的请求与复用完成结果，不记录身份标识原文或请求正文。

## 运行环境

### 运行中追加消息

同一所属用户、模型及系统指令下，已有历史之后仅追加用户/开发者/系统消息时，普通用户追加请求按 FIFO 等待原完整轮次结束，再在同一个原生会话中发送新增内容。原轮次发出工具后，工具结果请求不进入该队列，可优先回传并继续原任务；追加消息不会取消原 Prompt、撤销原工具或重放已完成动作。排队返回正常 `response.created` / `response.in_progress`（`stage=queued_followup`），沿用流式心跳，不伪造模型回复。队列不占 AGY 生成名额，即使生成名额只有一个，也能接收追加请求并让原工具结果继续通过。请求取消只移除对应排队项，保留原任务；断线续接沿用既有 30 秒宽限与请求重放规则。

追加队列全局最多四项；资源保护强制模式下，内部排队上限同时受全局/每用户并发上限减一约束，给原工具结果保留 HTTP 名额。严格限额不足以容纳排队时返回明确容量状态，不用排队占满名额。这个私有上限由门户写入，不接受外部调用者伪造。客户端已包含前一条排队提示、再追加下一条时，只提交新增后缀；原生期间生成的真实回复和工具结果保留。模型/系统指令改变、实质历史改写、工具结果、Codex 摘要及普通显式空工具名单仍使用各自校验路径。本机制是在桥接中安全排队后调用 ACP，不向同一事件队列并发启动多个原生 Prompt。

### 请求日志错误详情

门户请求日志中的 AGY 错误详情统一显示英文，沿用与其他渠道一致的 `HTTP <status> · <detail>` 格式。历史记录按原错误码映射显示，不改写存储数据；客户端 JSON/SSE 的错误文字、错误码及模型回答保持原样。会话正忙、摘要等待和工具结果缺失使用具体原因，流已开始后的门户最终状态按本地冲突/参数错误记录为 409/400，不再统一显示成未知上游 502。

门户与桥接在同一个容器、同一个 Go 进程中运行。`PORTAL_AGY_EMBEDDED=true` 启用内置桥接，内部 HTTP 仅监听 `127.0.0.1:18320`，MCP 使用另一临时回环端口；这些端口均不发布。AGY CLI 不编译进门户，也不包含在镜像或备份中。当前服务器基于官方 1.5.3 应用下述 512,000-token 检查点预算补丁，不能再称其为完全未修改的官方二进制。

`compose.prebuilt.yaml` 使用 `ops/agy/Dockerfile.runtime` 构建 Debian 运行基础镜像；`Dockerfile` 的源码构建同样使用 Debian 运行环境。启用 `compose.agy.yaml` 后，只读挂载宿主机 `/opt/cliproxy-agy/bin/agy`，读写挂载 `/var/lib/cliproxy-agy`。门户程序、数据、端口及 CPA/CPAMP 配置沿用原部署。运行用户为 UID/GID 10001；AGY 数据目录和门户密钥须归该用户所有，凭据 0600、私有目录 0700。桥接随门户容器统一启停，不提供独立服务入口。

内部服务密钥保存在 `/etc/cliproxy-agy/service.secret`，门户只读挂载其相同值 `secrets/portal_agy_secret`。不要将密钥写入命令行或仓库。运行配置如下：

```text
PORTAL_AGY_EMBEDDED=true
PORTAL_AGY_SECRET_FILE=/run/secrets/portal_agy_secret
AGY_COMMAND=/opt/cliproxy-agy/bin/agy
AGY_HOME=/var/lib/cliproxy-agy
AGY_MAX_SESSIONS=3
```

`AGY_MAX_SESSIONS=3` 限制并发请求槽位。常驻对话上限在“系统管理 → 资源保护 → 设置”调节，默认 3，范围 0 至 16，0 表示不限制常驻数量；配置保存在门户数据库中，保存后直接生效，重启时自动应用。降低上限只转存已完成且空闲的会话，生成、待工具回传或响应交付中的会话继续处理，完成后再收拢至上限。超过名额或空闲 10 分钟的已完成会话转存硬盘，通过官方会话恢复能力继续；正常生成和响应交付期间不转存。等待客户端工具结果不计作空闲，超过 10 分钟时先加密保存原响应链、完整历史、已交付调用 ID、已收到的结果与图片，再取消原生等待并释放常驻名额；写盘失败时保留原会话并在后续巡检重试。后续工具结果按同一用户、Key 与响应链/历史匹配，加载原官方会话后将实际结果作为已完成动作的上下文续接，不重新下发原客户端调用；未收到的结果不虚构成功，多工具批次须补齐后才继续。会话常驻期间只在内存更新，不在启动生成、交付工具调用、回传结果或正常回答完成时写入会话检查点；仅在移出内存、关闭或正常停机前保存。转存记录可跨进程重启恢复。超时、协议错误、连接中断、原生进程失效、主动停止和正常停机时尽可能补存最新历史、已交付调用及收到的结果。中断输出另行标记，保留部分正文，绝不登记成完成响应；恢复时根据真实客户端历史与结果重建，安全预算允许时附上中断输出作参考，不盲目重做已完成动作。正常停机先取消并等待处理中的请求补存，再关闭会话数据库；恢复到内存时只失效旧检查点的可恢复标记，避免强制退出后把已推进的原生会话配上过时历史；下次移出内存时保存最新状态。强制杀进程、断电或磁盘故障仍可能丢失未转存的内存进度。移除累计 256 个响应便取消健康会话的限制。账号退出/切换仍使旧映射失效，防止跨账号续接。磁盘不设数量上限，闲置超过 7 天自动清理受桥接管理的数据。门户及 CLI 共享容器内存上限，默认 1024 MB（1,024,000,000 字节），可通过 `PORTAL_CONTAINER_MEMORY` 调整。

常驻与硬盘会话共用同一套最终匹配规则。硬盘索引对工具调用 ID 作统一编号，兼容 Codex 改写 ID、调整相邻推理/调用顺序及补充可选 null 字段；候选仍须校验完整历史、函数参数、结果内容和调用对应关系。多条有效候选返回歧义错误，不按最新记录猜测。已有恢复索引在升级启动时分批重建一次，正常请求使用索引定位，不扫描全部存档。

`portal-sessions.db` 与官方 `agy/conversations/*.db` 位于独立持久化目录。恢复索引按用户和 Key 隔离、加密保存，数据库缓存有界；生成中或结果未知的会话不会在重启后自动重放。容器重建保留登录态及可安全恢复的已完成会话，整套备份重建仍只恢复凭据，不导入会话。

### 第四个请求如何处理

- 三个请求都在处理时，新请求最多等待 10 秒取得请求槽位，超时返回 `429 busy`。
- 常驻对话中有已完成且空闲的条目时，先将最久未使用的条目转存硬盘，再接入新对话。
- 常驻条目全部处于生成、等待客户端工具结果或响应交付中时，新建/恢复对话返回 `429 session_limit`，不挤掉正在处理的会话。
- 分段摘要同样占用常驻对话名额；额度刷新和账号操作也会使用请求槽位。长对话重建需要额外的摘要时间，不保证立即开始正式回答。

## 登录与模型

账号登录、退出和切换优先通过门户的“账号管理”完成。容器内官方 CLI 使用同一个持久化专用目录。

在上游管理点击“账号管理”：通过 Google 官方授权页面取得授权码或回调地址，再粘贴到弹窗完成登录。支持退出和切换账号，操作只对门户管理员开放并校验 CSRF。授权进程由官方 CLI 运行在临时隔离目录，10 分钟过期，关闭弹窗会取消；新授权失败不替换当前账号。切换成功或退出后结束旧运行会话并使旧响应链失效，避免使用新 Google 账号恢复旧账号上下文。过期清理仍管理原会话文件；客户端本地聊天记录不变。授权码不写入审计日志，也不通过门户查询或展示 Google Token。

官方 print 模式不接受 ACP 的目录参数，因此额度命令使用私有 `quota-home`，其默认凭据目录链接到同一 `agy` 目录，不复制 Token。该目录仍在专用系统用户的私有 home 内。

在终端登录时，在浏览器完成 Google 授权，将授权代码输入服务器终端。不能使用 CPAMP 的 OAuth JSON 替代这个流程。首次登录需要账号持有人操作。

在上游管理中点击顶部“刷新配置”，统一读取官方账号模型、各自档位声明和额度，不发送模型推理请求。额度使用官方 `agy -p /usage --output-format json`，按原始模型组、窗口、剩余比例和重置时间展示；仅显示官方实际返回的窗口，不补造 5H 或其他额度。账号卡片及共享额度池统一按 5H、7D、月额度的顺序显示，未知窗口保持相对顺序排在后面。额度成功缓存 10 分钟、失败节流 30 秒，并发读取合并，刷新配置可以强制更新。门户概览和用量页的共享额度池也以独立的“Antigravity CLI（ACP）”卡片展示同一快照，不包含账号身份；“刷新额度”接入原有的全局后台刷新、并发合并及冷却规则，AGY 与 CPA 的 Antigravity 额度保持分开。在“上游模型配置与调用预设”的统一弹窗设置模型启停、多个别名、保留原名和思考上限；在客户端模型同步弹窗设置下发模型和默认档位，脚本会下发 `agy/<模型ID>`。ACP 的 Extra 显式映射为客户端 xhigh；未声明值不补充。不再提供独立的渠道启停或管理员试用开关；正常门户审批、Key 状态和统一模型启停仍生效。AGY 已启用模型也在页面的配置摘要中展示；编辑早于 AGY 接入创建的预设时会补入当前已有账号的渠道目录，新增渠道模型默认未选择，保存草稿不改变现有路由。

门户通过 `compose.prebuilt.yaml`、`compose.gateway.yaml`、`compose.agy.yaml` 三个文件启动。先将同一内部服务凭据复制到 `secrets/portal_agy_secret`，所有者为门户容器 UID/GID 10001、权限 0600，再只重建门户容器。桥接仅通过容器内回环连接，不需要 Docker 网桥网关或公开内部端口。官方 CLI 和 AGY 数据目录按上述路径挂载。

## 当前范围与验证边界

DSH 的 Responses 接入配置与实际验证范围见 [DSH 接入说明](dsh.md)。AGY 专用模型需要声明上游思考档位，并配置 `compat.supportsMaxOutputTokens: false`。已完成会话在内存缓存满时转存硬盘，生成中和等待工具的会话不会因此被替换。

实现 HTTP Responses 流式/非流式、JSON 函数和自由文本工具封装、命名空间、挂起/回填、并行结果归属、取消、有限会话回收、模型管理，以及门户本地请求/分钟用量汇总。

已用官方 AGY 验证文字回复、函数及自由文本工具的流式回传、所有者隔离和重复结果拒绝。DSH 的文字、工具回传、多轮对话和长历史续聊已完成实际验证；真实 Codex 客户端验收尚未完成；管理员已选择向正常获准使用门户的用户开放该通道。单次发给官方 CLI 的文字输入保持 160 KiB 安全预算；超过预算的旧历史自动分段摘要，保留最新用户输入及近期交互原文，再建立会话继续。整个 HTTP 请求仍限 10 MiB。图片只接受内嵌图片，最多 64 张；旧历史中的图片随周围文字按原顺序送入多模态摘要，保留与任务相关的画面、可见文字和数值；无法辨认的细节由摘要注明。最新用户输入中的图片保留原样，不进入旧历史摘要。远程输入文件/图片 URL 和 WebSocket 不在当前兼容范围；`tool_choice` 已支持自动、禁用、必须、指定和允许工具列表。工具声明可在同一会话中新增、修改和撤销；模型与系统指令改变仍需新会话。自定义工具的格式会提供给模型，但不宣称具备 OpenAI 原生 CFG 约束采样能力。

`POST /v1/responses/compact` 接入同一套分段摘要，返回标准 `response.compaction` 外形及门户自有的 `compaction` 输入项。摘要经 AES-GCM 加密并绑定门户用户、Key 和实际模型；持有相同内部服务凭据的服务重启后仍可解密。它只能在本 AGY 通道重放，不能当作 OpenAI 官方加密上下文传给其他供应商；其他供应商的不透明压缩项仍拒绝。压缩接口需要完整 input，不接受仅 previous_response_id 的历史引用。当前账号存在生成中或待回传工具时拒绝显式压缩，防止遗失挂起调用。

摘要生成不注册任何客户端工具，每个旧历史片段均被处理。每段文字最多 96 KiB，图片最多 4 张，内嵌图片数据合计约 4 MiB 时换段；超过图片分段预算的单张合法图片独立发送，不切割、不丢弃。图片仍受整个 HTTP 请求的 10 MiB 限制，分段不放宽总上传限制。摘要未完成、过大、取消或上游失败时明确返回错误。最新用户输入或其尚未完成的一轮交互自身超过安全预算时仍需拆分。模型摘要有信息损失风险，原始客户端历史和门户交互记录保留；不会通过切掉早期文字伪装为成功。请求完整提交到桥接后，正式生成和历史摘要均不受门户的 60 秒无输出限制；客户端取消、官方错误或进程退出仍会终止处理。上传及向客户端实际写出响应时仍保留无进展保护。相同所有者与模型的历史分段复用受限缓存，缓存键包含图片原始数据、格式及顺序（最多 64 个摘要，空闲 10 分钟失效），减少客户端重复重放的开销。

Token 统计读取官方 CLI 1.5.3 会话数据库中已完成模型步骤的用量元数据。每个新原生轮次记录步骤游标，每次 HTTP 回复只累计游标后的新增步骤；工具调用和结果回传分别记录，避免把同一轮次的累计用量重复入账。只在回复结束边界读取小型元数据，不扫描整段对话，不在流式分片期间查询。输入包含缓存读取和写入，输出包含思考；缓存与思考是明细，合计仅为输入加输出，不重复相加。日志保留本次实际采用的思考档位，客户端未指定时读取 CLI 当前选项。缺失、无法解析或未经采集的历史用量仍显示未知，不用零或估算值补造。内部摘要会额外消耗官方上游额度，当前 Token 统计不代表包含精确的摘要消耗。HTTP 生成请求数及成功/失败按门户最终完成状态写入；内部摘要轮次、显式压缩接口与 MCP 保活不另计为用户生成请求。全局和个人用量、用户管理及日志从同一缓存来源读取本地补充数据；用量在请求结束写入时维护分钟增量汇总。

## 备份与重建恢复

普通门户数据库备份包含 AGY 模型配置、调用预设、客户端同步设置及请求统计。新版加密凭据快照（version 2）额外保存 Google OAuth 登录文件、内部服务密钥、AGY 安装身份，以及常驻数和内存限制；不归档会话、恢复索引、生成图片、缓存、日志或程序文件。登录态和密钥只进入加密备份，不出现在命令行或状态信息中；门户和运行服务密钥不匹配时停止备份。旧版凭据快照不再接受恢复，需要重新生成新版备份。

“重建并恢复”将 AGY 凭据与数据库置于同一恢复事务；门户容器启动及健康检查前，按内置定义准备外部 CLI、数据目录权限、只读密钥挂载及同容器回环连接。桥接逻辑来自当前可信门户程序；新机从 Google 官方地址下载固定版 CLI 并校验内置 SHA512，同机保留现有官方 CLI。不会执行备份中的程序、systemd 单元或脚本。外部 CLI 或容器启动准备失败时按恢复事务回退，不报告完整恢复成功；其余宿主机任务安装失败仍进入待重试阶段。恢复使旧会话映射失效，不自动重放挂起工具；原客户端可在新会话重新提交历史。普通“恢复”仅恢复门户数据库，保留当前 AGY 登录态和容器设置。Google 若撤销凭据或要求重新授权，仍需在账号管理重新登录。

### 长对话压缩与连接中断

Codex 本地压缩会通过普通 Responses 接口发送无工具的 `CONTEXT CHECKPOINT COMPACTION` 交接摘要请求。仅最终用户消息匹配固定两句指令、且未提供可调用工具时，桥接将其作为原会话摘要处理：按所属用户与 Key、响应链或严格历史匹配原 ACP 会话；原工具目录、加载工具、模型档位和系统指令保留，只在本次摘要期间采用 `tool_choice=none`，结束后恢复原工具策略。原会话正在等待客户端工具时，必须带齐本批次真实结果，随后把摘要指令随最后的 MCP 结果交回原执行；原 Prompt 已结束时，则将结果作为已完成动作上下文在同一原生会话生成摘要。只发送新增内容，不重新投递累计历史，也不另做多轮历史摘要。历史比较允许压缩器省略/改写 reasoning 摘要，但所有真实消息、工具名称、参数和结果仍须一致；原 reasoning 记录保留。冷缓存只在版本及历史校验通过后加载同一原生会话 ID，不因摘要的系统指令不同而重建。无法确认原会话、历史实质改写、工具还未完整交付、结果不齐或仍在独立生成时明确返回待续接/等待状态，保留原调用，不偷偷新建摘要会话、不虚构工具完成。普通请求显式空工具数组仍撤销工具，历史/引用中的标记不触发此分支。

这里的“原会话摘要”指 Codex 请求的交接文字生成，不代表强制原地删除 AGY 内部历史。Codex 随后用摘要改写客户端历史时，工作会话仍按既有严格对齐规则重建，以真正采用精简后的上下文。AGY 1.5.3 二进制保留单条用户输入默认 64,000 估算 token 的截断路径，序列化截断预算为 192,000 字节（187.5 KiB）；不能仅豁免桥接的 160 KiB 文本预算就声称完整超长历史已送达模型。该豁免实验未部署，已撤回。普通新建/重建工作会话及显式 `/responses/compact` 的安全预算与分段规则保持不变。

### 512,000-token 检查点预算补丁

2026-11-13 按用户指定的 [分析帖](https://linux.do/t/topic/3117832) 修改服务器 Linux x86-64 AGY 1.5.3 的 `utils.GetCheckpointConfig`：将原 256,000 上限比较、上限赋值及未知容量默认值改为 512,000，仅三条指令的六个字节；保留 `min(模型容量减输出余量, 512000)`，较小模型不会被抬高。没有改选付费上下文档位、解锁菜单、修改白名单、解除输入截断或修改工具权限。实际压缩触发仍取决于运行配置，这不是模型物理窗口或精确触发 token 数的保证。

可复核脚本为 `ops/agy/patch_context_512k.py`，默认只读计算；`--output` 独占创建暂存新程序，不覆盖输入、不创建备份。只接受原版 SHA256 `7ca212748ca0dfda718efbc39a776a104472e7e9344d4b6ea147c543684f96a3`，补丁后为 `8b4fc29f938cab08c47e7471238184fe77a6c9757e0d640bf980f133998a6f7c`。脚本在 Linux x86-64 执行实际补丁的最小值机器码，验证小模型及 512,000 上下边界；未发真实模型请求。上线须等待 AGY 无活跃/等待工具任务、门户到 CPA 无流量，再原子替换宿主机程序并重建门户，更新单文件只读挂载。不要直接写正在挂载或执行的文件。

本补丁仅修改累计上下文的检查点预算；160 KiB 桥接单次输入预算、192,000 字节原生单条输入截断及 Codex 自身压缩策略保持不变。CLI 升级或新机恢复下载官方版本后不自动应用补丁；必须重新核对新版本，不能盲目套用旧地址。当前同机恢复会沿用已有可执行文件。

已有会话的模型、系统指令或历史发生变化时可能需要重建，并将超预算旧历史分段摘要。摘要任务会产生实际 Google 模型调用和额度消耗，正式回答可能在摘要完成后才开始。模型进度仅根据实际摘要输出更新；流式生成的连接保活独立运行。非流式调用及显式压缩仍可能只向门户发送 HTTP 102，中间进度不等同于外层连接保活。

流式生成通过输入校验并取得处理名额后即发送 `response.created`，不必等到摘要或首个模型输出。交付层在静默时每 15 秒发送并刷新 `: keepalive` SSE 注释，覆盖首字等待、摘要、生成中途及重试复用；注释不写入响应复用缓存，不代表真实模型进展，也不计入 Token、请求数或长期交互记录。计时把连接握手与首个模型内容/工具动作分开，错误仍通过 `response.failed` 记录为失败。非流式 JSON 和显式压缩接口维持原协议，不注入 SSE；这些接口仍需考虑 Cloudflare 等外层代理自身的等待限制。客户端断开后的 30 秒续接宽限及会话保存规则保持不变；保活不影响 Google 容量不足、官方 CLI 的生成超时或真实进程错误。

目前门户在取得运行服务的正式响应前遇到传输错误，会将其记录为 `503 worker_unavailable`。这个标签也可能包含外部连接取消，不能单凭它判断 AGY 宕机或账号失效。排查时对齐门户请求时间、`gateway_request_timings`、Cloudflare Tunnel 日志及 `agy/log/acp-front-*.log`、对应 `acp-worker-*.log`；区分上传、摘要、正式生成和最终交付。不要记录或公开原始 Token、授权码及未脱敏请求内容。

## 监控与排查

维护时统一停止或重建门户容器，不再启停独立 AGY systemd 服务。需要取消接入时移除 AGY Compose 覆盖及门户 AGY 环境配置，再重建门户容器；保留数据和登录态。旧会话明确报失效，不自动转交 CPA 或其他账号。

系统管理将 AGY 纳入服务合计内存说明，第四张资源卡片显示常驻对话数/上限，请求卡片在待完成任务后内联注明“其中：AGY 任务”，不显示等待工具数量；管理概览隐藏 AGY 任务和常驻对话两行；均读取同一份缓存 5 秒的运行服务内存计数。管理概览的上游模型摘要复用统一账号和模型配置缓存，包含 AGY 的已启用模型，不触发模型目录发现、额度刷新或推理。
系统管理与管理概览的“模型上游”合并检查 CPA 模型接口及 AGY 桥接服务/登录状态；AGY 检查共享状态及账号缓存，不发送生成请求，不代表已验证 Google 侧模型推理或剩余额度。AGY 不可达、未登录或 CPA 不可达时分别注明；其他正常来源的模型摘要继续展示。

Codex 可自动附带 OpenAI 服务工具声明。`web_search` 和 `image_generation` 由官方 AGY 工具执行，不生成客户端 MCP 调用；托管文件搜索、代码解释器及未配置的服务在 Responses `metadata.portal_unavailable_tools` 返回声明列表，不阻断普通聊天。有效远程 MCP 声明走本节 broker，连接失败明确报错。未知工具类型、未声明本机环境的原生 Shell、空名称和重复名称明确报错。客户端 `tool_search` 及对明确延迟工具目录的服务端发现均已接入标准 `tool_search_call/tool_search_output`，后者不联网或调用另一个模型；实际文件操作仍由客户端执行。同步脚本为 agy/ 模型显式设置 `supports_search_tool=true`（客户端工具发现能力），并迁移旧目录；其他模型字段保留。

## 原生客户端工具格式

按“客户端声明并提供执行能力才接入”的规则，新增以下 Responses 格式转换：

| 客户端声明 | 返回调用 | 客户端回传 |
| --- | --- | --- |
| `shell`，且 `environment.type=local` | `shell_call` | `shell_call_output`，保留 stdout、stderr、退出码/超时和输出长度 |
| `local_shell` | `local_shell_call` | `local_shell_call_output`，支持通过原调用的 `id` 关联 |
| `apply_patch` | `apply_patch_call` | `apply_patch_call_output`，保留成功/失败状态 |
| `computer` | `computer_call.actions` | `computer_call_output` 中的内嵌截图 |
| `computer_use_preview` | `computer_call.action` | 同上，按客户端声明的显示尺寸校验坐标 |

这些类型复用现有 MCP 桥、工具名单、结果归属、增量工具更新和会话缓存；AGY 服务不执行命令、不修改文件、不控制服务器桌面。电脑操作的 MCP 展示使用较小的参数描述，避免被 CLI 延迟隐藏；调用仍按完整的动作规则校验。截图按真实图片回填。补丁失败作为工具错误交给模型处理，不伪造成功，也不等同于整轮模型生成必定失败。结果类型、调用 ID、退出状态或截图无效时不释放挂起操作；原生权限和客户端审批流程保持有效。

网页搜索、网页读取和生图仅使用官方 AGY 执行器。专用文件检索仍需要客户端提供函数或 MCP 工具，门户未安装文件索引服务。通用函数、自定义工具、客户端 MCP、终端/Python 执行以及工具图片回传按原有方式工作；官方搜索和生图的历史上下文兼容保留，不会重新执行历史工具。
