# Antigravity ACP 接入

CLIProxy Portal 可通过 Antigravity CLI 的 ACP 接口提供独立的 `agy/` 模型通道。客户端使用门户的 Responses API；门户在容器内完成 HTTP、ACP 和 MCP 之间的桥接。

本说明介绍通用配置、协议范围和会话行为。项目整体安装见 [项目首页](../../README.md)，DSH 客户端配置见 [DSH 说明](dsh.md)。

## 组件与执行位置

| 组件 | 工作 |
| --- | --- |
| 门户网关 | 验证用户和 API Key，检查模型启停，转交请求并统计结果 |
| ACP 桥接 | 维护原生会话、转换工具调用与结果、处理摘要和受限恢复 |
| Antigravity CLI | 提供官方模型、账号授权、模型目录及额度信息 |
| 客户端执行器 | 执行客户端声明的文件、终端、补丁和电脑操作工具 |
| 远程 MCP 服务（可选） | 在独立授权下执行该服务提供的工具 |

桥接与门户位于同一个容器、同一个 Go 进程中，内部 HTTP 与 MCP 端口仅使用回环连接。CLI 由宿主机只读挂载，不包含在项目运行镜像中。

网页搜索、网页读取和图片生成由官方 AGY 工具执行。客户端项目文件不会自动上传到服务器；读取或修改这些文件需要客户端提供相应执行器。门户不提供托管 Shell 或通用代码解释器。

## 安装与配置

先完成门户和模型网关配置，再准备支持 `agy acp` 的 Linux CLI。CLI 的安装来源及账号授权由安装者自行管理。

默认挂载约定：

| 宿主机路径 | 容器内路径 | 用途 |
| --- | --- | --- |
| `/opt/cliproxy-agy/bin/agy` | 相同路径，只读 | Antigravity CLI |
| `/var/lib/cliproxy-agy` | 相同路径，可写 | 账号凭据、原生会话和门户恢复索引 |
| `secrets/portal_agy_secret` | `/run/secrets/portal_agy_secret`，只读 | 门户内部服务凭据 |

以下从项目根目录执行，CLI 来源路径需要替换：

```bash
sudo install -d -m 755 /opt/cliproxy-agy/bin
sudo install -m 755 /path/to/agy /opt/cliproxy-agy/bin/agy
sudo install -d -m 700 -o 10001 -g 10001 /var/lib/cliproxy-agy

openssl rand -hex 32 > secrets/portal_agy_secret
chmod 600 secrets/portal_agy_secret
sudo chown 10001:10001 secrets/portal_agy_secret

docker compose -f compose.prebuilt.yaml -f compose.gateway.yaml \
  -f compose.agy.yaml up -d --build
```

应用于全新安装的密钥生成命令不应重复覆盖已有密钥。该密钥用于内部鉴权及加密状态，需与持久化数据一起保留。默认 Compose 网络、CPA 服务名与端口需要按安装环境配置。

[compose.agy.yaml](../../compose.agy.yaml) 提供以下主要设置：

| 配置 | 默认或示例值 | 用途 |
| --- | --- | --- |
| `PORTAL_AGY_EMBEDDED` | `true` | 在门户进程内启动桥接 |
| `PORTAL_AGY_SECRET_FILE` | `/run/secrets/portal_agy_secret` | 内部服务凭据文件 |
| `AGY_COMMAND` | `/opt/cliproxy-agy/bin/agy` | CLI 可执行文件 |
| `AGY_HOME` | `/var/lib/cliproxy-agy` | 持久化工作目录 |
| `AGY_MAX_SESSIONS` | `3` | 并发请求槽位 |
| `PORTAL_CONTAINER_MEMORY` | `1024000000` | AGY 覆盖文件中的容器内存上限，字节 |
| `AGY_CATALOG_REFRESH_EXPERIMENTAL` | `false` | 实验性目录刷新，默认关闭 |

门户及 CLI 共享容器内存。常驻对话上限由管理员在资源保护设置中调整，与并发请求槽位分别控制；默认 3，支持 0 至 16，0 表示不限制常驻数量。

## 账号与模型

管理员在上游管理的“账号管理”中完成 Google 官方授权、退出或账号切换。新授权失败时保留当前账号；切换成功或退出后，旧账号的运行会话和响应链失效，避免跨账号续接。

“刷新配置”读取官方账号、模型、思考档位和额度，不发送模型推理请求。模型启停、别名、保留原名和思考强度上限使用门户统一配置界面。额度按上游实际返回的窗口展示，不为缺失窗口补造数据。

客户端使用 `agy/<模型ID>` 或已配置别名，沿用门户审批与 Key 校验。可选模型和默认档位也可以通过 [Codex 同步脚本](../../internal/clientsync/README.md) 下发；目录中的上下文声明不会改变上游实际容量或收费规则。

## 接口范围

| 接口 | 行为 |
| --- | --- |
| `POST /v1/responses` | 流式或非流式生成，支持工具交接和会话续接 |
| `POST /v1/responses/compact` | 将完整历史转换为本通道可重放的加密摘要项 |
| `GET /v1/models` | 门户统一模型目录中的已启用模型 |

AGY 生成只通过 Responses 接口接入，不自动兼容其他供应商的全部 API 参数。远程输入文件、远程输入图片 URL 和 WebSocket 不在该通道兼容范围。

支持 JSON 函数、自由文本自定义工具、命名空间、并行工具结果、客户端工具发现和内嵌图片。`tool_choice` 支持自动、禁用、必须使用、指定工具和允许工具列表。自定义格式作为模型说明提供，不代表具备其他供应商的原生约束采样能力。

单个请求上限为 10 MiB，图片最多 64 张。桥接发给 CLI 的单次文字安全预算为 160 KiB；它是字节限制，不是模型的 token 上下文窗口。

## 工具调用与结果

客户端声明可调用工具，门户将调用交给对应执行器；客户端以原 `call_id` 回传结果。工具的所属会话、名称、参数规则、结果类型和执行来源都会校验，批次及工具更新全部通过校验后才释放等待。

同一会话可以新增、修改和撤销工具。省略 `tools` 沿用当前目录，显式空列表撤销；延迟加载工具经发现或引用后才开放。目录变化不会重新启用已撤销工具，调用时仍校验当前原始 schema。

原生客户端格式包括：

| 声明 | 调用 | 回传 |
| --- | --- | --- |
| `shell`，本机环境 | `shell_call` | `shell_call_output` |
| `local_shell` | `local_shell_call` | `local_shell_call_output` |
| `apply_patch` | `apply_patch_call` | `apply_patch_call_output` |
| `computer` / `computer_use_preview` | `computer_call` | `computer_call_output` |
| 客户端工具发现 | `tool_search_call` | `tool_search_output` |

文字、结构化内容和内嵌图片按实际结果回填。图片保留为多模态内容，不通过下载远程 URL 或读取服务器路径代替客户端回传；无效图片在唤醒工具前拒绝。结构化大整数保留精度，工具明确失败可作为结果传给模型判断。

官方生图回传真实 PNG、内嵌预览和有效期内的原图下载链接。可选服务未接入时，响应通过 `metadata.portal_unavailable_tools` 说明能力缺失，不伪造工具执行。

## 远程 MCP

带 `server_url` 的 MCP 声明由独立 broker 接入公共 HTTPS Streamable HTTP 服务；初始化与工具发现使用该服务的独立授权。示例中的地址和令牌需要替换：

```json
{
  "model": "agy/<模型ID>",
  "input": "读取已授权文档服务中的项目记录",
  "tools": [{
    "type": "mcp",
    "server_label": "docs",
    "server_url": "https://mcp.example.com/mcp",
    "authorization": "<远程服务的 bearer token>",
    "allowed_tools": ["read_record"],
    "require_approval": "always"
  }]
}
```

默认要求审批，调用前返回 `mcp_approval_request`。后续请求通过原响应链回传匹配的 `mcp_approval_response`，并重新提供工具声明及该服务授权。只有明确设置 `never` 才跳过审批；批准本身不代表执行成功。

执行结果返回自含的 `mcp_call`，不再给客户端派发同一操作。声明、凭据或权限范围改变时重新校验。远程 bearer 不写入模型定义、普通日志或恢复快照，不使用门户凭据替代远程服务凭据。

最多配置 4 个远程服务。只接受公共 HTTPS 地址，拒绝私网、回环、重定向和 URL 内嵌凭据；不支持 legacy SSE transport。执行结果未知时不自动重发外部操作。

## 会话、重试与中断恢复

会话按门户用户、Key、模型及历史归属匹配；已有响应链和客户端会话标识可帮助定位，但不能绕过历史校验。相邻推理记录顺序、可选 null 字段或工具 ID 的兼容处理均受完整内容核对约束；有歧义时不会猜测合并。

同一会话中仅追加用户或指令消息的请求，可排队等待原轮次结束。真实工具结果请求不进入普通追加队列，避免阻塞原任务。队列最多 4 项，并受门户可用并发名额约束。

相同请求优先复用正在交付的输出或完成回复缓存。客户端断开后保留 30 秒重连宽限；完成回复缓存有效期为 10 分钟。缓存有容量上限，不代表所有任务都能在进程退出后无损恢复。

未完成交接需要恢复时，严格核对原请求和会话状态，只允许一次受限自动接管：

- 已收到的真实结果保留，已确认成功的操作不重复执行。
- 明确失败的结果交给模型按实际错误和当前指令判断。
- 未收到结果的操作标为 UNKNOWN，默认跳过、不重试、不自动核实；继续独立工作并暂缓依赖步骤。
- 用户明确要求核实时，使用可用只读检查；证据不足仍保持未知。
- 恢复失败保留错误原因及可续接标识，允许后续新消息继续。

跳过后迟到的真实 function/custom 结果，可在核对原调用后追加更正事实。原 UNKNOWN 声明保留，相同结果重传不重新推理或执行工具，已有真实结果不允许被改写。收到回执不自动证明成功；结果仍不明确时继续默认跳过。忙会话保留在途任务并拒绝冲突补交。

## 持久化与资源

完整会话在常驻期间更新内存，仅在移出内存、关闭、中断或正常停机等边界保存，不在每次输入、工具派发、结果回传和正常完成时写入完整快照。完成回复缓存与轻量状态记录使用各自的保存规则。

原生会话及加密恢复索引位于 `AGY_HOME`。索引保留响应链、完整历史和必要的工具交接状态，按用户与 Key 隔离；正常请求按索引定位，不扫描所有会话正文。闲置超过 7 天的数据由后台清理。

已完成且空闲的会话可以转存硬盘。等待工具的会话超时释放前先保存交接状态，保存失败则保留等待；后续结果仍需通过原调用校验。强杀、断电或磁盘故障可能丢失尚未归档的内存进度。

并发槽位满时，新请求最多等待 10 秒，超时返回 `429 busy`。无法安全转存活动会话时，新建或恢复请求可返回 `429 session_limit`，不会为接收新任务挤掉在途工作。

## 长对话与压缩

普通新建或重建请求的旧历史超过文字预算时，会分段摘要并保留最新输入及近期原文；图片随周围文本进入多模态摘要。最新输入本身超限仍需拆分，摘要失败不会以静默截断伪装成功。摘要会消耗上游额度，也可能丢失语义细节；调用与结果事实另有校验和加密索引保留。

Codex 的固定交接摘要请求可以在原会话生成摘要。工具仍在等待时，必须带齐真实结果；独立生成尚未结束或历史无法对齐时，返回等待或冲突状态。摘要期间临时禁用工具，结束后恢复原策略。客户端随后用摘要替换历史时，工作会话可能按新的历史重建；在原会话生成摘要不等于删除 CLI 内部历史。

显式压缩接口产生本门户自己的加密摘要项，绑定用户、Key 和实际模型，仅可在本 AGY 通道重放；不能作为其他供应商的官方加密上下文。压缩需要完整 input，不接受仅凭 `previous_response_id` 代替历史。

仓库另提供 [检查点预算补丁工具](patch_context_512k.py)，只适用于脚本校验的特定 Linux x86-64 CLI 二进制。该工具不是基础接入前提，也不会自动应用；累计检查点预算、单条输入截断、桥接字节限制和客户端压缩阈值分别生效，修改其中一项不能扩大其他限制或上游物理窗口。

## 连接、用量与排查

流式请求通过校验并取得名额后发送 `response.created`，静默期间每 15 秒发送 SSE 保活注释。保活不表示真实模型进展，不进入模型输入、回复缓存或 Token 统计。非流式 JSON 及显式压缩接口不插入 SSE；客户端和外层反向代理仍有各自的超时规则。

用量从 CLI 已完成模型步骤的元数据增量读取，缺失时显示未知，不用估算值补造。实际模型用量与 HTTP 是否完整交付分别记录；内部摘要也会产生上游消耗。

后台工具回执对已知客户端执行器的标准返回格式分类：退出码 0 为正常结束，非零为失败，进程尚未结束为运行中；退出码 0 但带 PowerShell 异常记录或 Python traceback 时单独标为包含异常，策略或参数校验拒绝标为未执行。分类同时记录来源及可取得的退出码，无法识别的结果保持 unknown。文本分类是诊断信息，不证明文档内容正确或外部操作已完成，也不用于放宽恢复校验或自动重试。门户耗时详情不逐条展示这些回执，原始工具结果保持原样。

门户请求日志中的 AGY 错误详情使用英文，客户端 JSON/SSE 保留原协议与错误说明。排查时按请求时间、响应 ID、会话阶段及工具状态关联，区分等待槽位、摘要、上游生成与结果交付；未收到工具结果不等于客户端没有执行。

CLI 最终失败时，客户端错误 message 保留原有摘要，错误码和 HTTP 状态映射保持不变。门户错误详情优先显示当前请求经 ACP 通知或 RPC 错误传来的原始诊断，常见凭据脱敏，保留大小写、换行及本轮尚未恢复的重试诊断；无诊断时回退到英文归类摘要。诊断经内部认证响应的私有 trailer 传给门户并记录于请求失败详情，不转发到客户端。中间通知不结束重试，重试成功后不记录旧诊断。诊断最多 64 KiB，超过时保留开头和末尾并明确标记截断；不读取整份进程日志或其他会话的 stderr。

输入校验失败保留具体错误码，例如不支持的历史项目、其他供应商的加密上下文、无效指令和远程图片引用，不统一记成上游生成失败。CLI 的中间错误通知不提前结束本轮重试；最终仅剩执行终止通知时按失败处理，并优先保留本轮已取得的具体上游原因。流式回复通过失败事件报告最终结果，日志中的本地校验错误、限流错误分别保留对应状态。

## 备份与重建恢复

AGY 备份保存登录凭据、内部密钥及必要配置，不包含会话和 CLI 程序。重建恢复需要重新准备 CLI；Google 撤销授权或要求重新登录时，仍需账号持有人重新授权。

容器重建可沿用持久化目录中的会话状态，但备份恢复不用于跨机器导入历史会话。范围、目录及恢复流程见 [备份文档](../backup/README.md)。
