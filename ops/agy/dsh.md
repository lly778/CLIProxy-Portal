# DSH 接入 AGY

DSH 使用 `llm-pi-ai` 的 `openai-responses` 路由连接门户。官方 AGY 及 Google 登录态位于服务器；工具通过门户返回 DSH，由 DSH 的权限和工具执行流程在客户端处理。

## 模型配置

在当前 DSH profile 的 `cordis.patch.yml` 中，给已有供应商增加模型。凭据仍使用 DSH 的凭据管理，配置中只填写引用名称；不要把 API Key 写入补丁。

```yaml
- id: llm-pi-ai
  config:
    providers:
      cpa:
        apiKeyEnv: PORTAL_API_KEY
        api: openai-responses
        baseURL: https://api.example.com/v1
        transport: sse
        models:
          - id: agy/gemini-3.8-flash
            name: AGY Gemini 3.8 Flash
            reasoningEfforts:
              low: low
              medium: medium
              high: high
            compat:
              supportsMaxOutputTokens: false
```

将此条模型合并到已有 `models` 数组，保留其他模型和供应商。`reasoningEfforts` 以门户从官方账号读取的声明为准；示例中的 Gemini 声明为 low、medium、high，不补充 off、xhigh 或 max。

当前 AGY ACP 未提供每请求 Token 输出上限。DSH 的 `supportsMaxOutputTokens: false` 显式关闭该模型的 `max_output_tokens` 请求字段；门户仍拒绝此不支持的参数。这一项必须放在 AGY 模型自身的 `compat` 中，保留其他模型的输出上限行为。

在 DSH 中选择这个模型，或者设置默认选择：

```yaml
- id: agent-default-model
  config:
    provider: cpa
    model: agy/gemini-3.8-flash
    reasoningEffort: high
```

门户配置 AGY 并登录 Google 账号后，已审批用户可使用自己的有效门户 Key 调用管理员启用的模型；不再提供渠道总开关或“仅管理员试用”开关。配置修改后，完全退出并重新打开 DSH，再发送消息。

## 验证记录

2026-11-09，使用本机 DSH 桌面版所带的 headless 入口、同一 `llm-pi-ai` 适配器及 Agent 工具循环，通过门户的公网 Responses 地址验证：

- 普通文字回复成功。
- DSH 实际读取临时文件，工具结果回传后，模型正确输出了提示中未提供的文件随机字符串。
- 同一聊天连续读取两个文件，两次调用及结果均正确匹配。
- 新建聊天成功；返回原聊天并携带完整历史继续操作成功。
- 约 295 KiB 的合成已有历史自动分段摘要后，成功找回位于开头、中间、末尾的三个随机事实；其后继续本机文件读取和工具回传成功。
- 公网 `/v1/responses/compact` 将超过 160 KiB 的历史压缩后，返回绑定当前用户与 Key 的加密项；把它传回 `/v1/responses` 后仍正确找回三个原始事实。

测试只使用独立 DSH home 和临时文件，未让模型修改项目。已完成会话达到常驻名额上限时转入硬盘，生成中、等待工具及仍在交付响应的会话保留。现在仅携带有效 `previous_response_id` 也能恢复磁盘中的已完成会话；超过 7 天未使用、已取消且未完成的交互或崩溃时尚未结束的交互仍不可恢复。

长文字历史不需要在 DSH 端放大窗口来绕过 413：门户在新建/重建会话时处理超过单次预算的旧文字，并保留当前输入。原生同一会话继续使用增量输入；已有客户端摘要也可按普通文字重放。旧历史中的图片由同一压缩流程读取并摘要，最新用户输入中的图片保留原样。单次请求 10 MiB、最新输入本身过大及挂起工具边界仍按 [AGY 接入说明](README.md) 处理。

另通过公网 Responses HTTP/SSE 实测图片压缩：约 191 KiB 的旧文字与历史图片自动生成摘要后，模型正确找回仅出现在旧图片中的随机编号，同时读出最新图片中的另一随机编号；显式 `/v1/responses/compact` 保留最新图片原始数据，其加密摘要重放后两个编号仍正确。测试图片由脚本临时生成，编号未写入文字提示；本轮图片测试直接调用 HTTP 接口，未通过 DSH 桌面或 Codex 客户端操作。


2026-11-09，另通过公网接口验证会话磁盘恢复与内存：

- 同一 Key 建立五个独立聊天，始终最多三个常驻 worker；第一个聊天转存后，仅提供旧响应 ID 和新问题，仍正确输出只在原聊天中出现过的随机事实，未重新上传历史。
- 整个 AGY 服务的 cgroup 内存：一个短对话约 201 MiB，两个约 326 MiB，三个约 451 MiB；五个聊天切换和磁盘恢复后约 474 MiB，观测峰值约 496 MiB。这些是短文字样本，不是长历史或大图片的内存保证。上限设为 768 MiB。
- 运行服务重启后恢复带客户端工具的会话，重新绑定 MCP 后，工具调用和结果回传成功，原始随机事实与新工具结果均保留。
- 仅将一个已转存的测试聊天的索引时间改为 8 天前，后台分钟定时器随后自动删除其索引及原生会话数据库；未直接调用删除接口或清理用户聊天。

此历史测试记录不代表已验收所有 DSH 插件或功能。长时间工具等待和取消未在本次 DSH 测试中验收；当时的压缩接口验证使用 HTTP 格式完成。用户随后已进行真实 Codex 调用，具体工具和图片显示仍需逐项确认。

2026-11-09，补充通过公网 Responses 验证逐步 Token 采集：普通回复、同一会话的流式续聊、工具调用与流式工具结果回传均返回实际输入、输出、缓存、思考和合计；客户端省略档位时也返回 CLI 当前默认档位。工具往返按新增步骤计量，不重复累计旧步骤。缺失元数据的旧请求仍显示未知；内部摘要另有上游消耗，不包含在这些用户生成请求的精确统计内。

## 工具、并发与长对话

- 文字函数、自由文本工具、客户端 MCP、工具发现和图片结果使用同一桥接；本机 Shell、补丁、电脑操作由实际客户端执行器处理。专用文件搜索依赖客户端提供函数或 MCP；门户没有独立文件索引或托管代码解释器。
- 网页搜索、网页读取和生图由官方 AGY 的 Google 工具执行。旧客户端同类工具声明会被过滤，避免混用。官方生图返回 PNG 原生结果、内嵌小图预览及原图下载链接，图片显示情况取决于客户端。
- 默认最多 3 个常驻对话，独立请求可并发。请求槽位满时最多等 10 秒后返回 `429 busy`；生成和工具等待中的对话不被新请求挤掉，无可替换条目时返回 `429 session_limit`。空闲对话按 30 分钟转存，磁盘保留 7 天。
- 客户端重复发送完整历史时，桥接会校验历史前缀并尽量续接；历史改写、切换模型或系统指令变化可能引起重建和分段摘要。摘要可能推迟正式回复，客户端应保留合理的请求等待时间和重试提示；错误取消后的请求不会伪装成成功。

AGY 的登录凭据与重建范围见 [备份与重建恢复](README.md#备份与重建恢复)。服务器备份不包含 DSH 本机配置或聊天数据。
