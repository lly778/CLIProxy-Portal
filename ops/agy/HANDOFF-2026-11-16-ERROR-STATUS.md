# AGY 输入校验与终态错误修复（2026-11-16）

## 问题与改动

只读核查 15:16 与 15:17 两笔记录发现两个问题：前一笔 HTTP 400 在模型生成前被输入校验拒绝，具体码被 Tracker 的白名单归一化成 agy_generation_failed；后一笔在原生 CLI 发生多次 RESOURCE_EXHAUSTED/429 重试并最终终止后，仅返回 `⚠ Agent execution terminated due to error.`，桥接将其当成普通正文清除原错误，错误地完成响应。

- 增加本地输入校验错误的安全描述与状态映射，覆盖指令格式、历史类型、不透明/加密上下文、图片、工具和输入预算。Tracker 保留明确错误码，日志不再统一泛化为上游生成失败；摘要只用固定描述，不复制请求正文、私有 URL 或未知错误原文。
- 识别 CLI 的固定最终终止提示，不把它输出为正常助手正文。若本轮已有具体上游错误，保留该原因；没有具体原因时返回 agent_execution_failed。是否最终失败仍等待原生 RPC 结束，中间提示不取消或重发 Prompt，真正恢复后的正文/新工具仍能清除临时错误。
- 泛化 RPC 执行错误不覆盖更具体的本轮原因；取消、传输或其他明确 RPC 错误仍保留。摘要流程同样拒绝仅有终止通知的“成功摘要”。普通文本引用和示例不触发固定终止提示识别，上一轮提示不泄漏到下一轮。
- 错误对象与 status=completed 并存时，Tracker 不再同时保留完成状态。流式终态按实际错误归类，429 限流保留 429，本地输入错误保留 400/413；门户错误详情用英文，客户端原有具体错误说明保持原样。
- 历史请求和用量记录没有批量改写。无法从既有日志还原 15:16 被泛化前的具体输入字段；本次修复使后续错误保留原因，不猜造旧记录。
