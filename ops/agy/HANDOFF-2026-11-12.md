## 5. 最新修复的实现

### 5.1 具体错误原因显示

`internal/agy/upstream_failure.go`：

- 只分类原生 RPC 错误或 CLI 警告，不解析普通助手回答为服务错误。
- 将已识别原因映射为固定、安全的错误代码和说明。
- 例如 `No capacity available` → `upstream_capacity_exhausted`，说明“上游模型容量不足”。
- 不把原始诊断中的 Token、账号、URL、Prompt 等直接暴露给用户。
- 无法识别的错误明确回退“具体原因未能识别”，不能虚构原因。
- `FailureSummary` 生成现有日志格式可读取的 JSON，沿用 `gateway_request_timings.failure_reason` 与 `agy_requests.reason`；不增表、不增加页面查询。

`rpc.go`、`manager.go`：从 RPC 和 CLI 警告分类错误。

`tracker.go`：既识别 SSE `response.failed`，也识别非流式顶层 `error` JSON；只接受已知错误代码。

`internal/gateway/agy.go`：保存明确原因，避免只留下 `agy_request_failed`；不覆盖已经确定的上传、客户端写出或网关空闲超时原因。

旧记录已丢掉的错误原因**不会自动补写**。

### 5.2 不提前打断官方重试

旧问题有代码与日志两方面证据：

- `manager.update` 见到 `⚠ API error` 就发 `agentEvent{Err:...}`。
- `responses.go` 立即 `out.fail`、退出；defer 保存后 `drop`，发送 `session/cancel` 和 `session/close`。
- 实例：16:41:51.787934 官方 CLI 写“attempt 1 failed ... retrying in 4s”，16:41:51.794506 已收到 `session/cancel`，仅约 7 毫秒。

新处理：

- `session.promptWarning` 保存当前原生 Prompt 的警告，仅存内存。
- `manager.update` 收到已识别警告后只记录，不发终止事件、不把临时警告当回答输出。
- 后续正常 `agent_message_chunk` 清除警告；新的非 failed 工具调用也清除；旧工具状态更新和思考片段不会清除。
- `startPrompt` 在每次原生 Prompt 开始前清空警告。
- `finishPrompt` 在原生 `session/prompt` 最终返回后决定结果：若仍有警告，即使 CLI 返回 `end_turn` 也不能算成功；泛化的原生错误可用此前具体警告补足。
- 不能用旧容量警告覆盖客户端取消、进程断开或另一明确终止错误。
- `compact.summaryTurn` 改为复用 `startPrompt`，摘要任务获得相同处理。
- **没有在门户新加循环重试、累计失败上限或冷却机制。重试由官方 CLI 自身决定。**

## 8. 后续只读诊断方法

### 内部状态（不触发模型生成）

先获取门户容器 PID，再在它的网络命名空间内访问 `/internal/status` 或 `/internal/account`。Bearer 使用 `/root/cliproxy-portal/secrets/portal_agy_secret` 的内容，只在脚本内读取，绝不打印。

```text
GET http://127.0.0.1:18320/internal/status
```

状态 `active_sessions` 缺失表示零。`sessions` 是常驻数量，不等于正在生成数量；等待工具的会话还应结合状态与客户端请求判断。

### 数据库与日志

- SQLite 以 `file:/绝对路径?mode=ro`、`uri=True` 打开，只查询目标时间/用户范围。
- `users.phone` 找 user_id，凭据不回显。
- `agy_requests`：`started_ms,ended_ms,status,reason,duration_ms,response_id,timing_id`。
- `gateway_captures` 用 `cpa_request_id='agy:'+timing_id` 关联，`status_code` 是采集到的实际 HTTP 状态。
- `gateway_request_timings` 有阶段计时与 FailureReason。
- 门户详细时间与交互采集有保留数量限制；老记录可能已删除，但 `agy_requests` 仍在。
- 原生 CLI 日志：`/var/lib/cliproxy-agy/agy/log/acp-worker-YYYYMMDD_HHMMSS-*.log`。
- 日志行常为 `I1112 08:41:51.787934 ...`，不是 ISO 日期。过滤时按实际格式匹配。
- 只提取容量错误、重试次数/间隔、cancel/close、结束时间等诊断，避免打印全文 Prompt/工具参数/认证信息。
- `journalctl --since` 明确带 `UTC` 或 `Z`，仅加 `--utc` 不足以改变输入时间的解析。
- 不要扫描或解密其他用户不相关对话；按本次失败用户和时间范围调查。
